# 巴别塔（回译）

X 阅读、跨语言回复与 Markdown 写作浏览器扩展。0.4.5 改进本机 Pi 桥接的错误与文字处理，写作台支持宽窗口并排和窄窗口抽屉布局。

## 0.4.5：Pi 错误原因更明确

本机桥接在两分钟超时、回复超过 100000 字符或错误输出过多时，终止请求并提示原因。空输出和启动失败也会明确提示；分块返回的中文字符保持完整。升级桥接文件后请重启本机服务。测试使用模拟子进程，真实 Pi 模型连接仍需在本机配置后验收。

## 0.4.4：多窗口修改保留双方内容

两个写作台打开同一文稿时，保存会核对加载时的版本。如果另一窗口已修改原稿，你的修改会另存为「冲突副本」，并自动转到副本继续编辑。参考来源和文件夹保留，原稿不会被旧窗口覆盖；副本使用独立助手会话。

## 0.4.3：明确保存失败，方便重试

文稿写入失败时，顶部持续显示「保存失败」和「重试保存」，编辑区保留当前内容。恢复存储后点击重试，成功才显示「已保存」。编辑时也可按 Ctrl+S（Mac 上为 Command+S）立即保存。

## 0.4.2：等待助手时继续保存

写作助手的模型请求和文稿保存分别排队。等待 Pi 回复时，继续编辑的文稿可以自动保存，也可检查连接状态；连续对话仍依次处理，清空会话会等当前回复结束后执行。

## 0.4.1：保留备份中的文稿修改

备份预览显示写作台文稿数量。同一文稿在本地和备份中有不同修改时，保留本地版本并另存备份副本；重复导入同一备份不会重复生成文稿副本。文件夹和参考来源随文稿保留。无效文稿或合并后超过 200 份文稿的备份会在写入前拒绝，并提示先整理资料库。

## 写作与回复

- 在 X 阅读页点击「保存全文到写作台」，将当前帖子或文章收进「参考文章」文件夹；写作台也可从剪贴板保存参考资料、创建文件夹、移动文稿。
- 回复页的「插入 X 草稿」在 X 回复弹层中优先选择唯一编辑框，并核对原帖链接或唯一的帖文正文；确认后才写入，不点击发布。
- Agent 使用 [Pi](https://pi.dev/docs/latest/cli-integration) 本机桥接。先安装并配置 Pi，在项目目录运行 `node pi-bridge/server.mjs`。将启动窗口显示的令牌填入插件设置，保存并点击「授权并检测」。模型可留空使用 Pi 默认配置。
- 「复制 X 文章排版」将 Markdown 转为富文本写入剪贴板，并打开 X 文章编辑页。请在编辑器中粘贴，检查标题、列表、链接和图片；X 对粘贴格式的实际保留程度取决于其编辑器版本。本功能不会发布文章。
- 本机当前未安装 Pi，也没有已登录 X 的可验证会话，因此真实 Pi 对话与 X 页面交互尚需在你的环境中验收。
## 0.4.0：更清楚的入口，更专注的写作

点击插件图标，可以直接进入 X 阅读与回复，或打开自由写作台。设置页分为「模型连接」「阅读与回复」「写作助手」「离线词典」「收藏表达」「数据与备份」「实验功能」；切换页面保留表单输入，点击底部「保存全部设置」才生效。

写作台在宽窗口中并排显示文稿库、编辑器与助手，在窄窗口中通过「文稿库」「写作助手」按钮打开抽屉。按 Escape 可关闭抽屉或 X 侧栏。X 侧栏聚焦页签后可用左右方向键、Home 和 End 切换功能。

升级前可在「数据与备份」导出内容。继续使用同一个安装目录并重新加载扩展，才能保留原扩展 ID 下的数据。

## 下载与安装

1. 从 [GitHub Releases](https://github.com/Kevin-Yixuan/babel-tower-backtranslation/releases) 下载版本号最高的 `babel-tower-backtranslation-*.zip`，解压到一个**长期不移动**的目录。确认该目录的第一层就是 `manifest.json`。
2. Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`，开启「开发者模式」，选择「加载已解压的扩展程序」，选中刚才的目录。
3. 到 `x.com` 或 `twitter.com` 刷新页面。帖子下方会出现「翻译」「回复」入口；插件图标可打开设置。
4. 使用模型功能前，在设置中选择服务商并填写自己的 API Key。可先点「测试连接」；此操作会产生一次真实模型请求。

**从旧版升级：**先备份旧扩展中的草稿与收藏，再把新版文件更新到**旧扩展原来的同一目录**，在扩展管理页点「重新加载」，刷新 X。不要先移除旧扩展，也不要换一个新目录安装后期待数据自动出现。不同安装目录可能得到不同的扩展 ID，本地数据不会跨 ID 自动迁移。详见 [安装与更新](安装与更新.md)。

## 自动更新状态：没有自动更新

本项目**不包含任何自动更新机制**。早期设计中的本地 PowerShell 更新器（`update-unpacked.ps1`）、完成标记（`update-marker.json`）、每日任务轮询与扩展强制重载整套方案**从未发布、已整体退役**，相关脚本与标记文件不在仓库中，也不会进入任何发布包。

当前唯一支持的更新方式是手动原地更新：下载新 ZIP，把运行文件覆盖进**同一个安装目录**，在扩展管理页点「重新加载」。完整步骤见 [安装与更新](安装与更新.md)。

每次合并到 `main` 且自动化测试通过后，GitHub Actions 会构建社群预览 ZIP 与 SHA-256 作为流水线产物；**合并或 Release 都不会自动更新浏览器里已安装的扩展**。面向普通社群成员的无脚本自动更新只能通过 Chrome Web Store／Microsoft Edge Add-ons 渠道实现；本扩展**尚未上架任何浏览器商店**。

## 能做什么

- 点击「翻译」后，默认自动检测原文语言并译成中文；阅读侧栏可独立选择原文／译文语言、交换方向，按「当前全文」「划选内容」「手动输入或粘贴」选择取材。文章正文延迟出现时会继续读取；单段超过 20,000 字符会明确提示拆分，不会悄悄截断。
- 划选英文单词时补全词界并查词；句子可进入侧栏讲解或收藏。本地 MDX 词典可选，在线兜底查词会把单词送往词典服务。
- 用中文写想法生成目标语言回复，先给完整可编辑文本，再给中文回译、意思风险、具体改法和后续建议。模型内容仍需你核对；插入 X 编辑框前必须再次确认，扩展绝不点击发布。
- 在「回译」「成长」中做练习、保存句子与记录亲写稿的错误。工作台草稿只有在你明确确认「本人亲写」后才参加成长记忆归纳。
- 可选 Jev 规则折叠与兴趣高亮，默认关闭；启用后会把附近帖文和规则发给 TypeSafe，和折叠功能共用每日调用上限。

## 数据与额度

打开「翻译」页签或选句进入阅读，当前帖文或文章段落会自动发往你配置的模型，可能消耗额度。生成、检查、讲解及主动测试连接也会调用模型。Jev 启用后会自动判断附近帖子。扩展没有自建中转服务器；API Key、草稿、收藏、设置与导入的词典索引保存在浏览器本地。扩展本地存储不是操作系统钥匙串，请勿在共用浏览器中保存私人密钥。

用户可编辑全局 init prompt；随包默认文本仍是**临时默认值**，正式版本尚未提供。输入材料被提示词标为引用，结构化回复也做字段检查，但真实模型可能犯错或编造事实，请在发布前自行核对。四家真实模型、真实 Jev API、真实登录态 X 页面及 Chrome 手工加载仍需社群实际测试。发现问题请在 GitHub Issues 中附浏览器版本、复现步骤及去敏后的页面结构；不要上传密钥或私人帖子内容。

## 开发与验证

扩展源码无需构建或 `npm install` 即可加载。`npm test` 运行 Node 测试；浏览器测试先安装 Playwright（或用 `PLAYWRIGHT_PATH` 指向已有模块），再运行 `npm run test:browser`。浏览器测试使用隔离 Edge 配置、本地仿真 X 页面及受控模型响应，不访问真实已登录 X，也不使用真实模型密钥。发布 ZIP 仅包含运行文件和安装说明。
